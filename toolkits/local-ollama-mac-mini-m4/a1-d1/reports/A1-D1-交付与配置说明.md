# A1 / D1 交付与配置说明

本文件说明两个插件的接入方式、全部配置项、以及在真实 profile 中启用前必须满足的前提。配套示例见 examples/ 目录。

## 一、安装（不依赖网络与 pnpm）

插件是零依赖 ESM，可整目录复制进 profile：

1. cp -R packages/dsh-local-first-router ~/.dsh/profiles/<profile>/node_modules/dsh-local-first-router
2. cp -R packages/dsh-budget-guard ~/.dsh/profiles/<profile>/node_modules/dsh-budget-guard
3. 在 profile 的 package.json 的 dsh.profile.bundles 数组末尾追加两个包名（顺序即 patch 叠层顺序：base → headless → 插件 → 用户 cordis.patch.yml）。
4. 在 profile 的 cordis.patch.yml 里按 examples/cordis.patch.example.yml 写入用户层配置。
5. 自检：dsh <profile> --dump-config | grep -A6 local-first-router（应看到用户层值，而不是 bundle 默认值）。

注意：--dump-config 中每个插件 id 会出现两次（bundle 默认层在前、用户层在后），核对配置时必须看最后一次出现。

## 二、dsh-local-first-router 配置

| 键 | 默认 | 说明 |
| --- | --- | --- |
| policy | local-first | local-only：一律本地，不看内容；local-first：按关键词分类，命中走云端、否则本地 |
| local.provider | （空） | 本地 provider 名，必须与已注册 adapter 一致 |
| local.model | （空） | 本地模型 id |
| strictSticky | true | true 时同 session 后续 turn 复用首次决策 |
| respectRecordedSelection | false | true 时若会话已有 model/selection 记录则不覆盖 |
| allowedRemoteProviders | [] | 空数组表示不限制云端 provider 名；非空则只允许列出的 |
| classifier.cloudKeywords | 内置若干 | 正则源串数组；命中即判 cloud |
| logFile | （空） | 不为空则写 JSONL：router-mounted / route / route-locked |

路由日志字段：t、sessionId、messageId、kind（local|cloud）、provider、model、rule（如 policy:local-only、keyword:云端、default:local）、decidedAt（epoch ms）、textChars。

行为保证：

- 决策发生在 agent/inbox/inserted，早于本步 model.current()。
- 一旦判 local，本 session 的 llm/stream 若出现其它 provider，会被 LOCAL_ROUTE_LOCKED 直接终止（不调 next，零出网）。
- retry 与 replay 不重新路由：粘性表按 session 命中，llm-retry 重试同一请求不会再次触发 inbox 事件。

## 三、dsh-budget-guard 配置

| 键 | 默认 | 说明 |
| --- | --- | --- |
| mode | observe | observe：只记录不拦截；enforce：真正拒绝超预算请求 |
| ledgerFile | （空） | enforce 下必须非空，否则一律 BUDGET_NO_LEDGER |
| perRequestYuan | 0.2 | 单次请求上限（CNY） |
| dailyYuan | 2.0 | 单日上限（CNY），按本地日期分桶 |
| freeProviders | [] | 命中则不预留、不读账本（本地 provider 应放这里） |
| prices | {} | { provider: { inputPerMTok, outputPerMTok } }，单位 CNY / 百万 token |
| defaultReserveOutputTokens | 1024 | 请求未给 maxTokens 时的预留输出量 |
| inputTokensPerChar | 0.5 | 输入 token 估算系数（与 chars/4 取大） |
| lockTimeoutMs | 5000 | 抢账本锁的超时，超时即 fail closed |
| lockStaleMs | 30000 | 锁文件 mtime 超过该值视为陈旧并回收 |
| releaseOnError | false | true 时失败的请求立即释放预留；默认保留未决预留 |
| logFile | （空） | JSONL：guard-mounted / reserved / settled / free / denied / pending-kept |

失败码：BUDGET_NO_LEDGER、BUDGET_UNKNOWN_PRICE、BUDGET_PER_REQUEST、BUDGET_DAILY、BUDGET_LEDGER_ERROR。全部为 fail closed（拒绝而非放行）。

重要限制：**这不是全局预算守卫**。它只覆盖经过 llm/stream 的调用；Web Search、Search/Fetch、以及绕过 ctx.llm 的第三方插件收费出口不在覆盖范围内。

## 四、生产接入示例（未执行，需评审）

目标形态：本地模型通过 pi-ai 的 OpenAI 兼容 provider 接入，router 指向它，guard 对云端 provider 计量。

前提：

1. 先确定本地运行时与模型（Ollama / vLLM / llama.cpp），并把 baseURL、模型 id 填进 pi-ai 的 providers 配置。示例中一律使用占位符：<LOCAL_BASE_URL>、<LOCAL_MODEL_ID>。
2. **qwen3-coder-30b 与 8080 端口明确不作为默认值**，仅为可能的候选，需另行确认。
3. 云端 provider 的价格必须按真实计费口径填写；未填写的 provider 会被拒绝（这是预期行为）。

## 五、启用前的自检清单

- [ ] --dump-config 中 router 的 local.provider 与 pi-ai providers 的键名一致。
- [ ] guard 的 freeProviders 含本地 provider（否则本地调用也会被要求预留）。
- [ ] guard 的 prices 覆盖所有允许的云端 provider，且数值与真实计费一致。
- [ ] ledgerFile 指向持久目录（不要放临时目录），并确认该文件不会被其它进程清理。
- [ ] 先用 observe 模式跑一天，核对 guard.jsonl 里的金额量级，再切 enforce。
- [ ] 确认 dailyYuan 的时区语义（按本地日期分桶）。
- [ ] 接受「失败请求保留未决预留」的行为，或显式开启 releaseOnError。
