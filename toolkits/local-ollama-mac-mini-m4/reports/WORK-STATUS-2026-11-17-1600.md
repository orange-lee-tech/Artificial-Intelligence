## 4. 模型架构与已确定决策

### 保留 4B

`Qwen3.5-4B` 官方模型卡描述 4B FFN 架构，不是 MoE。它不应被当作“专家稀疏模型”，但适合保留为轻量模型和基准。

### MoE 35B 试验方向

`Qwen3.5-35B-A3B` 官方模型卡：35B 总参数、约 3B 激活、256 experts，每 token 8 routed experts + 1 shared expert。它是候选模型，不代表已经验证在本机可运行。

### 三层路由分工

1. **Token-level MoE Router：** 模型内部每个 token 选择当前层 top-k experts。
2. **SSD Expert Streaming Runtime：** 从外置 SSD 按需读取被选中的专家权重，维护有界缓存；非专家 trunk、共享权重、当前专家和 KV cache 仍占统一内存。
3. **PACS Task Router：** 在任务级选择 4B、MoE、确定性工具链或云端模型，并受 Budget Guard 约束。

### 16GB 资源策略

- 模型文件在外置 SSD，不代表运行时零内存。
- 首轮并发=1、单模型执行槽；4B 与 MoE 不同时驻留。
- 初始从短上下文（4K）开始，再测试 8K；限制输出和并发。
- 专家 cache 先用运行时保守默认值，实测后再调，不预设缓存 GB 数。
- 监控 Memory Pressure、swap、runtime RSS/footprint、SSD I/O、expert cache hit/miss、TTFT、tokens/s 与任务质量。
- 持续内存压力、swap thrashing 或系统卡顿即停止/卸载 MoE runtime。

### Runtime 兼容性纪律

- `IDAH-BITBOX/serve-mlx` 是 pre-release、loopback、single-user、一次一个生成请求的 SSD expert streaming server。
- 公开 README 列出的 tested checkpoints 包括 Qwen3.6-35B-A3B-8bit、Qwen3-30B-A3B-4bit、Gemma 4。
- 不能因为模型都叫 Qwen MoE，就认定 Qwen3.5-35B-A3B 已在该 runtime 验证。
- `ddalcu/mlx-serve` 支持表包含 Qwen3.5 MoE 架构，但架构支持不等于 SSD expert paging。
- 首个 pilot 优先选择 SSD streaming runtime 明确列出的 tested checkpoint；若选 Qwen3.5，先做架构/权重格式/专家张量/路由/量化兼容性审计。
